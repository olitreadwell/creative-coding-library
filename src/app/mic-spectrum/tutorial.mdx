# Tutorial: Mic Spectrum

By the end of this tutorial you will understand how the Web Audio API splits sound into frequency bins and how the sketch reads those bins to draw each bar.

## Predict

The analyser node uses `fftSize = 2048`, which produces `2048 / 2 = 1024` frequency bins. The sketch draws fewer bars than that by sampling every Nth bin.

If you increase the number of bars shown, do you expect more detail in the high frequencies or the low frequencies? Think about which end of the frequency range has more bins.

## Run

1. Click "Enable microphone" and allow access. You should see bars appear immediately, even in a quiet room.
2. Hum a steady note. Watch which bars respond most. Hum a higher note and compare.
3. Clap once near the microphone and watch the bars spike across all frequencies momentarily.
4. Adjust "Smoothing" to a high value. The bars now decay slowly after a sound ends. Lower it and they snap back quickly.

## Look closer

- The audio graph connects three nodes: a `MediaStreamSource` (the microphone), an `AnalyserNode` (which computes the FFT), and nothing at the output end. No sound plays through your speakers.
- `getByteFrequencyData` fills a `Uint8Array` where each value is 0 to 255. The sketch maps those values to bar heights.
- Each bar's color comes from a colorblind-safe ramp. The ramp maps position (left to right) to a hue that reads correctly across common forms of color vision difference.
- On cleanup, every `MediaStreamTrack` is explicitly stopped. This turns off the microphone indicator light in your browser.

## Break it

- Try the "Bars" slider at minimum. Very few bars appear, each representing a wide frequency range.
- Try "Bars" at maximum. More bars show, but the high-frequency bars may stay nearly silent in a quiet room.
- Speak in a quiet room with "Gain" at maximum. You should see the bars move even for soft speech.
- Change "Smoothing" to 0. The bars should flicker rapidly with no memory of the previous frame.

## Recap

Four steps power any audio-reactive sketch: ask for microphone access, build a tiny audio graph with an analyser node, read the FFT data each frame, and draw based on those values. This sketch does all four.
