## How it works, step by step

This app uses [two.js](https://two.js.org/) to create and animate vector shapes. No canvas pixel-writing. Each shape is an object you update by changing properties.

### Step 1: build the grid

`gridPositions` returns an array of `{x, y, row, col}` objects. Each entry is the pixel-center of one cell. We create one `Two.Rectangle` for each entry and place it at that position.

```ts
const cells = gridPositions(COLS, ROWS, CELL_SIZE, CELL_SIZE);
// cells[0] → { x: 24, y: 24, row: 0, col: 0 }
```

A **scene graph** means two.js keeps a list of all shapes internally. When you call `two.play()`, it calls your `update` callback every animation frame, then redraws the graph. You do not write draw calls yourself.

### Step 2: measure distance from center

Every shape gets a `distance` value: how far it sits from the grid center, normalized between `0` (center) and `1` (corner). This single number drives everything else.

```ts
export function centerDistance(row, col, cols, rows): number {
  const cx = (cols - 1) / 2;
  const cy = (rows - 1) / 2;
  const dx = col - cx;
  const dy = row - cy;
  const raw = Math.sqrt(dx * dx + dy * dy);
  const maxRaw = Math.sqrt(cx * cx + cy * cy);
  return maxRaw === 0 ? 0 : raw / maxRaw;
}
```

`Math.sqrt(dx * dx + dy * dy)` is Euclidean distance: the length of the straight line between two points on a grid.

### Step 3: rotate each frame

Inside the `update` callback, we add a small angle to each shape's `rotation` property every frame:

```ts
rect.rotation += 0.008 + distance * 0.014;
```

Shapes closer to the center (`distance` near 0) rotate at `0.008` radians per frame. Shapes at the edge rotate faster. **Radians** are just another way to measure angles: one full turn is `TAU` (about 6.28) radians.

### Step 4: pulse the scale

`pulseScale` returns a number between `0.5` and `1.2`. It uses `Math.sin` to oscillate smoothly. The key part is the **phase offset**: each shape's distance delays it in time, so the pulse appears to travel outward.

```ts
export function pulseScale(distance, time, spread, minScale, maxScale): number {
  const phase = time - distance * spread; // each shape lags behind the center
  const t = (Math.sin(phase) + 1) / 2; // convert -1..1 to 0..1
  return map(t, 0, 1, minScale, maxScale);
}
```

Setting `rect.scale = s` makes two.js scale the shape around its own center. No position math needed.

### Step 5: shift the color

Hue starts at blue-purple (center) and shifts toward teal (edges). Each frame we add a `hueShift` based on `Math.sin(t - distance * TAU * 0.5)`. This ties color change to the same wave as the scale, so the colors pulse with the shapes.

```ts
const hueShift = Math.sin(t - distance * TAU * 0.5) * 20;
const lightness = map(s, 0.5, 1.2, 0.4, 0.7);
rect.fill = hslString(hsl(baseHue + hueShift, 0.75, lightness));
```

`hsl(hue, saturation, lightness)` is a color model. Hue is the color name (0-360). Saturation is how vivid. Lightness is how bright. Tying lightness to scale means big shapes look brighter.

## Try this

- Change `COLS` or `ROWS` to `20` to make the grid denser.
- Set `spread` in `pulseScale` to `0` to make all shapes pulse together instead of in a wave.
- Swap `rect.rotation +=` for `rect.rotation = t + distance` to get a frozen angle that depends only on position.
- Change the `baseHue` range from `260, 180` to `0, 120` to shift from blue to a red-green palette.

## What to remember

- A **scene graph** lets you describe shapes once and update them by property, not by redrawing.
- **Transforms** (rotation, scale) happen around a shape's local center, making math simple.
- A **phase offset** by distance turns per-shape timing into a visible wave. This pattern works for any oscillating value.
