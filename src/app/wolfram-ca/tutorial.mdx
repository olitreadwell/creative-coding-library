## How it works, step by step

This app draws Wolfram elementary cellular automata with plain Canvas 2D. No library. Here is the whole thing, broken into small pieces.

## Step 1: what the rule number means

An elementary CA rule is an 8-bit integer. Each bit maps to one of the eight possible 3-cell neighborhoods:

| Neighborhood | Bit position |
| ------------ | ------------ |
| 111          | 7 (MSB)      |
| 110          | 6            |
| 101          | 5            |
| 100          | 4            |
| 011          | 3            |
| 010          | 2            |
| 001          | 1            |
| 000          | 0 (LSB)      |

Rule 90 in binary is `01011010`. Reading from bit 7 down: 0,1,0,1,1,0,1,0. So neighborhood 110 -> 1, 100 -> 1, 011 -> 1, 001 -> 1, everything else -> 0. That is the XOR of left and right neighbors, which is why rule 90 makes the Sierpinski triangle.

## Step 2: computing the next row

The core function is `nextRow`. It takes the current row as a `Uint8Array` of 0/1 values and a rule number. For each cell it reads the three-cell neighborhood, converts that pattern to an index 0-7, then extracts the corresponding bit from the rule byte.

```ts
function nextRow(row: Uint8Array, rule: number): Uint8Array {
  const len = row.length;
  const out = new Uint8Array(len);

  for (let i = 0; i < len; i++) {
    const left = row[(i - 1 + len) % len];
    const center = row[i];
    const right = row[(i + 1) % len];

    // 3-bit index: left is MSB, right is LSB.
    const neighborhood = (left << 2) | (center << 1) | right;

    // Extract that bit from the rule.
    out[i] = (rule >> neighborhood) & 1;
  }

  return out;
}
```

Edges wrap around (toroidal). The leftmost cell's left neighbor is the rightmost cell.

## Step 3: filling the canvas

The canvas is divided into a grid of small square cells. The width tells us how many cells fit across (columns). The height tells us how many rows we can draw downward.

Starting from a single 1 in the center, we call `nextRow` once for each row and store all the generations. Then we loop over every cell and write its color into an `ImageData` buffer. One `putImageData` call paints everything at once, which is faster than drawing cell by cell.

```ts
const generations: Uint8Array[] = [firstRow(cols, "center")];
for (let r = 1; r < rows; r++) {
  generations.push(nextRow(generations[r - 1], rule));
}
// ... then write to ImageData and call ctx.putImageData()
```

## Step 4: DPR awareness

The canvas is sized in physical pixels using `window.devicePixelRatio`. On a retina screen that might be 2x. The CSS size stays the same, but the buffer is twice as wide and tall, so lines stay sharp instead of blurry.

## The four preset rules and what to expect

- **Rule 30**: chaotic. No repeating pattern. Used by Wolfram as a PRNG.
- **Rule 90**: Sierpinski triangle. A fractal built from XOR.
- **Rule 110**: complex and irregular. Proven Turing-complete.
- **Rule 184**: traffic flow model. Blocks of cells move right.

## Try this yourself

- Type any number from 0 to 255 in the rule input and watch the pattern change instantly.
- Notice that most rules (like 0 or 255) produce trivial results: all dead or all alive after one step.
- Rule 90 and rule 30 start from the same single cell but diverge completely. That gap between them is where most of the interest in CAs lives.

## What to remember

Eight bits. One lookup. Repeat thousands of times. That is the entire algorithm. The complexity you see is not hidden in the code. It is in how simple local decisions interact when applied simultaneously across a row, generation after generation.
